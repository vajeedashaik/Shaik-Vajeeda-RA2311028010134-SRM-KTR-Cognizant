Reference copy from the live project at Solutions/6. Spring Data JPA + Hibernate/EmployeeManagementSystem/. See ex1's NOTE.md for how to run the project.

Two independent datasources: PrimaryPersistenceConfig wires the primary one (Employee/Department, jdbc:h2:mem:testdb, marked @Primary) and AuditPersistenceConfig wires a second one (AuditEvent, jdbc:h2:mem:auditdb) — each with its own DataSource/EntityManagerFactory/PlatformTransactionManager bean and its own @EnableJpaRepositories basePackage, per Spring Boot's documented multi-datasource pattern. AuditService writes to the audit datasource independently of whatever transaction is active on the primary one (no XA/distributed transaction spans both — see the comment in AuditService.java for why that's an acceptable tradeoff for an append-only audit trail).

Because manually-built EntityManagerFactory beans don't get Spring Boot's automatic spring.jpa.hibernate.ddl-auto -> hibernate.hbm2ddl.auto translation, both persistence configs set hibernate.hbm2ddl.auto=update directly via .properties(...) on the builder (see the comment in PrimaryPersistenceConfig.primaryEntityManagerFactory) — omitting this left both databases schema-less at startup during testing.

Verified: server log showed both HikariCP pools connecting to their respective JDBC URLs, both persistence units initializing, and `insert into audit_event` running after every employee/department create/update/delete.
