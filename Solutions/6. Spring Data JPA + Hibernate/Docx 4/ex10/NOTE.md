Reference copy from the live project at Solutions/6. Spring Data JPA + Hibernate/EmployeeManagementSystem/. See ex1's NOTE.md for how to run the project.

Hibernate-specific annotations: @DynamicInsert/@DynamicUpdate on Employee (generated INSERT/UPDATE statements only reference non-null columns), @BatchSize(20) on Department.employees (reduces N+1 selects when that collection is initialized for several departments in one session). application.properties sets hibernate.jdbc.batch_size=20 plus order_inserts/order_updates=true. Employee.id uses GenerationType.SEQUENCE rather than IDENTITY specifically because IDENTITY defeats Hibernate's JDBC insert batching (it needs the generated key back after each row, forcing one round-trip per insert) — EmployeeService.bulkInsert(List<Employee>) is the batch-processing demo this enables.

Verified: POST /api/employees/bulk with 2 employees returned both with sequence-generated ids, and schema.sql-equivalent `create sequence employee_seq start with 1 increment by 20` appeared in the startup log.
